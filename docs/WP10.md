# WP10 — Imports and tree tools

From [Update 1](updates/UPDATE-1_Build_Specification.pdf) (ADR-048). Decisions in ADR-049.

## What was built (10 Nov 2026)

- **Preview before importing.** Choosing a GEDCOM file in the Archive offers "Update [an earlier tree]" or "Add it as a separate tree", then a preview: how many people would be added and updated, people in the tree who aren't in the file (kept), IDs the tree already uses for someone else (added as new, never overwritten), and the health check as it would be after the import. The preview runs the real import inside a transaction that's rolled back, so it's exact and nothing is saved.
- **Updating from a new export.** Each imported tree has its own identity, so a new export from Ancestry or elsewhere updates the people already there instead of adding them again. People are matched by their ID in that tree, and the match is only trusted if the names share a word. Newer imported facts take over from older ones; the user's own corrections still win; nothing is removed.
- **Health check after every import**, with the count in the import report (Update 1: "runs after every import and on request").
- **Undo in one step.** Every import, update, merge and removal is a change set recording what it created, what it changed (with a copy of before) and what it removed (with a full copy). "Undo this import" is on the import report, and the family page's "Changes and undo" lists every change. Undo is refused, with the reason, if a later change touches the same people (undo that first) or the user has since added facts to people the change brought in.
- **Merge preview.** "Merge a duplicate into this person" (also reached from the health check's "Compare and merge" on possible duplicates) shows every question side by side, highlights answers that differ, and lets the user untick any of the other record's facts. Relatives, residences and tree IDs move across; a parent and child can't be merged; living-status and parent mismatches are warned about.
- **Safe removal.** "Remove this person" shows what goes with them and who would be cut off from the tree (people only connected through them). Those are kept as a separate branch unless ticked to be removed too.

## Acceptance (Update 1, WP10)

| Done when | Status |
|---|---|
| A real exported tree imports cleanly and its problems are listed | Synthetic trees import cleanly and the problems are listed in the preview and report. Not yet tried with a real export: the owner's sister's Ancestry tree is the first real test |
| Merge preview: accept some facts and reject others | Passes (tests and browser) |
| Bulk change: one undo removes the whole branch | Passes for imports, updates, merges and removals |
| Explained suggestions, never only "other trees say so" | Duplicates are suggested only from the tree's own names and dates, with the reason shown |
| Tree health check runs after every import and on request | Passes |
| Safe deletion offers to keep or remove stranded people | Passes. "Reconnect" (linking them to someone else) isn't built yet |
